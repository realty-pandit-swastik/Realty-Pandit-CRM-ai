**2026-06-10 SHIPPED + live-verified.** Bug: Inventory page "Share via WhatsApp" (and External-Lead view "Send WhatsApp") showed "Sent" but the client received nothing.

**Root cause:** both surfaces POST `/api/inventory/:id/share-to-client` ([routes/inventory.ts:938](clients/sunny-sharma/projects/reality-pandit/agents/backend/src/routes/inventory.ts#L938)) which sent a **raw free-form** `WhatsAppService.sendText`/`sendImage` — NOT a template. Meta rejects free-form messages **outside the 24h customer-service window** (HTTP 400 #131047) and rejects **relative image paths** (`/uploads/...`). The error was swallowed at 3 layers (`sendText`/`sendImage` catch+never-throw; circuit breaker silent fallback; endpoint set `whatsapp_sent=true` unconditionally) and the frontend showed "Sent" on any HTTP 200. Map of share surfaces: only **Deal → Match & Share "Company WhatsApp"** used the template (`shareSpecificProperty`→`sendPropertyCard`→v4); Inventory + External-Lead used the raw endpoint; "Personal WhatsApp"/"Share Link" are wa.me (agent's own phone).

**Fix (no DB/schema/migration):**
- Added exported **`shareInventoryCard(phone, inv)`** in [property_sharing.ts](clients/sunny-sharma/projects/reality-pandit/agents/backend/src/services/property_sharing.ts) — mirrors `shareSpecificProperty`'s param build, resolves an absolute reachable image via `pickSendableImage`, calls `sendPropertyCard` (preferred **rp_property_card_sale_v4 / _rent_v4**, fallback v2). Returns true only if Meta accepted (sendTemplate→`callWhatsAppAPIStrict` **throws** on failure, so the boolean is real).
- `share-to-client` endpoint now does `whatsappSent = await shareInventoryCard(normalized, inventory)` instead of raw send → fixes BOTH Inventory page and External-Lead view (same endpoint, via `shareToClient`→[client.ts:174](clients/sunny-sharma/projects/reality-pandit/agents/frontend/src/api/client.ts#L174)).
- Frontend now surfaces the REAL result: `InventoryList.handleBatchShare` + `MatchedPropertiesSection.handleSendWhatsApp` mark **failed** when `whatsapp_sent===false` (ShareToClientModal already did). 
- `whatsapp.ts sendWithRetry` now logs Meta's `error.response.data` (the exact code, e.g. #131047) — previously only the generic axios message was logged, hiding WHY.

**2026-06-10 follow-up 2 — deal share unified on v5 + re-send non-blocking.** (a) Deal → Match & Share "Company WhatsApp" (`shareSpecificProperty`) AND auto-share (`shareNextProperty`) now call `shareInventoryCard` (v5) instead of `sendPropertyCard` (v4) — so ALL four surfaces (Inventory, External-Lead, Deal manual, Deal auto) send the same category-correct v5 card with link. `buildV5Card` works on a `MatchedProperty` too (typeName ← `prettifyType(type)`). (b) The inventory `share-to-client` endpoint NO LONGER early-returns on a prior `PropertyShare` — re-sending is ALWAYS allowed; it returns `already_shared` + `previously_shared_at` for a non-blocking notice and writes a NEW share row. Frontend (`InventoryList` bulk, `ShareToClientModal`) show "✅ sent" + "⚠ Previously shared on <date> — re-sent". Live-verified: deal share → `res_sale_v5`; the originally-stuck Gyan Khand re-sent (rows 1→2, `already_shared:true`+`whatsapp_sent:true`, UI notice shown). Bundle `index-CurmCGN0.js`, stamp `v20260610b`.

**2026-06-10 follow-up — v5 templates (link + category-correct).** Created **8 APPROVED UTILITY templates** `rp_property_card_{res,res_plot,com,com_plot}_{sale,rent}_v5` (Image + body w/ clickable property link `{{7}}` + 3 quick-reply buttons) via `backend/src/scripts/submit_property_templates_v5.js` (resumable image upload → header_handle; app `1868797817103904`). `shareInventoryCard` now `buildV5Card(inv)` → picks the template by `inv.category` (res/com; agricultural→com) + type-slug `/plot|land|orchard/` (plot) + `intent` (sale/rent), and builds **BHK for residential, type[+rooms] for commercial, plot-area for land** (kills the old "3BHK Office" mislabel); fallback v5→v4. Registry entries in `whatsapp_templates.ts` (7 params p1–p7, headerType IMAGE). Design doc: `docs/plans/2026-06-10-property-share-templates-v5.md`. Deal "Company WhatsApp" path still on v4. To create more image-header templates, reuse the submit script's resumable-upload pattern (no header_handle helper existed before).
