## Implemented safeguards and tested limits

- Native staff sessions now use independent identifiers, hashed rotating refresh credentials, absolute expiry, live agent/tenant checks and revocation. A global native-credential boundary covers legacy public workflows that decode optional staff identity themselves, including mixed cookie/bearer and bearer-case variants. Browser cookie login, CSRF and logout have real-auth compatibility coverage.
- Generic tasks/projects now derive tenant/team scope from Agent ownership and validate linked records. Reads, nested tasks, writes, reassignment, statistics and bulk import are guarded. Legacy orphan/system-owned task or project rows with no provable tenant-owned Agent are hidden; do not guess their tenant. Other workflow-task surfaces still need their own parity/security pass.
- Lead/deal per-object guards now match tenant and record/team visibility. Appointment reads and status/notes/cancellation writes repeat tenant, responsible-employee and linked-record boundaries; updates validate the canonical status enum, dates and assignees. Creation/rescheduling/provider acceptance remains a separate open workflow. Inventory catalogue/browse/search, detail and generated PDFs are tenant-bounded; media changes require the owning team. Document authorization includes tenant membership, and finalized paperwork cannot bypass that through static uploads. Public listing photos and intentional signed document routes remain available.
- Partner admin tokens previously selected the first tenant. Issuance and authenticated use now resolve the partner's actual Contact/Tenant, validating active status while preserving existing signed partner sessions and the default-deny route fence. Partner native rotating sessions remain unimplemented.
- Builder verification no longer accepts a demo OTP when storage has no code. Missing/down-store regression checks fail closed. Builder OTP replay/rate limits and the broader native builder session contract remain release blockers.
- Routine request logs use route templates, excluding identifier paths and capability queries. Broader legacy capture/error-handler logging still needs a dedicated pass; no claim of complete log remediation is made.
- Follow-up review closed malformed native bearer bypasses before optional-identity workflows, excluded auth/serialized request bodies and case-insensitive credential headers from error telemetry, and restricted calendar assignee serialization to public identity fields. Subsequent real-auth regressions reproduced and closed calendar nested-property owner/location disclosure using canonical inventory redaction and task-detail nested-project disclosure using the existing ID/name projection; see [CALENDAR_PRIVACY_EVIDENCE.md](CALENDAR_PRIVACY_EVIDENCE.md). These checks are not broad privacy certification. Focused real-auth/database and actual telemetry-callback evidence is recorded in [SECURITY_REVIEW_EVIDENCE.md](SECURITY_REVIEW_EVIDENCE.md); this does not certify unrelated logging/provider flows.
- Startup recovery and request recovery share one client credential rotation. Ordered SecureStore writes and generation/promise fences prevent obsolete saves/refresh failures from clearing or adopting a newer identity. Focused deferred-race tests cover these paths. Native draft first use exposed an Expo Crypto prebuilt/core ABI mismatch; the supported narrow `buildFromSource: ["expo-crypto"]` override fixed it. The corrected pre-patch Android client passed encrypted write/plaintext-negative file inspection, loaded-form offline/edit/reconnect/process-death restore, lead conflict/confirmed overwrite and explicit task create/clear. Pre-patch discard, font1.3/density360/background-return/picker-cancel, logout vault/key purge and other-session revocation→401 passed; 16 current pre-patch images were opened/accepted and two diagnostics excluded. Fresh patched-client acceptance and separate final design review remain pending. Development Fast Refresh observations are not release lifecycle acceptance. See [DRAFT_EVIDENCE.md](DRAFT_EVIDENCE.md).

Pending wizard uploads still share a staging media directory, including image-shaped documents. That workflow is not integrated into native UI and remains blocked pending an authenticated staging-file contract that preserves web previews. Finalized document uploads now validate size, extension/MIME and basic PDF/image/Office signatures, using UUID storage names independent of metadata. This is signature validation, not a malware scanner or complete file-format parser. Ambiguous native attachment upload now blocks another POST until a successful explicit current-server check plus user review/confirmation; failed/offline/background refresh cannot unlock retry. Six component regressions cover lost/malformed responses and input retention. This is not server deduplication or a durable process-death ledger; a deliberate retry or a late server completion can still duplicate data. Interrupted-upload cleanup, orphan reconciliation and broad private-media retention still require acceptance. See [ATTACHMENT_RECONCILIATION_EVIDENCE.md](ATTACHMENT_RECONCILIATION_EVIDENCE.md). Native v1 attachments currently accept bounded JPEG/PNG/PDF files; office formats, HEIC/video/mixed-media and exact personal WhatsApp recipient behavior are not claimed.

No unrestricted query cache or customer snapshot is persisted by the native app. Lead-note and new-task drafts use bounded AES-256-GCM files with a device-only SecureStore key, authenticated origin/tenant/account/role/session/form partitioning, 24-hour expiry, 64-KiB plaintext/80-file/two-revision limits and purge fencing. Tests cover corruption, transplanted ciphertext, interrupted writes and session races; Android acceptance covers only the stated draft subset. Assigned-record snapshots remain not started, and task/project edit forms have no process-death guarantee. Exported brandless PDFs are temporary app-cache files, purged on logout/identity change and checked for ten-minute expiry when re-entering sharing; background/process-death cleanup remains a release gap, explicitly marked in code.

All unresolved scope findings block only their affected capabilities. Device credentials, customer payloads and full private URLs must never enter telemetry or evidence. The local synthetic fixtures and mocked provider transports used in tests do not prove production/provider acceptance.
