## Encrypted drafts and purge semantics

Implemented forms: lead notes (`notes`, `baseNotes` for conflict comparison) and new task (`title`, `description`, `date`). Envelope also contains saved time, partition and form kind. `src/storage/useEncryptedDraft.ts` partitions by API origin + tenant + account + role + session + form; filenames hash scope/kind. `src/storage/drafts.ts` uses AES-256-GCM with authenticated scope/kind and a separate SecureStore device-only key `rp.mobile.drafts.key.v1`. Ciphertext files live in `Paths.document/rp-drafts-v1`.

- Expiry is 24 hours, checked on draft reads/writes; there is no background timer guaranteeing deletion at exactly 24 hours. Plaintext is capped at 64KiB; storage at 80 files with two retained revisions per form. Corrupt/expired candidates are deleted on access; successful explicit save/discard removes that form draft.
- `SessionController.clear()` invalidates credentials/request generation; `SessionProvider` clears queries and calls draft/key deletion plus share purge. Identity adoption clears sensitive caches on account/tenant/role change. Logout first requires successful server session revocation, then clears locally. A failed/offline logout is not a completed purge or revocation; no offline local-lock alternative is implemented.
- Invalid/revoked sessions are rejected server-side; client HTTP 401 clearing detects that boundary when requests/recovery run. This is not instantaneous remote erasure of an offline device. No offline writes/sends or automatic mutation queue exist.
- Missing draft install directory rotates a potentially surviving iOS keychain key. Refresh-key uninstall/reinstall behavior remains OS-specific; do not claim every credential is erased by uninstall. [Expo SecureStore](https://docs.expo.dev/versions/v58.0.0/sdk/securestore/) documents platform persistence and backup constraints.
- Android config enables SecureStore backup handling. Generated manifest references module backup/data-extraction XML: include shared preferences and exclude `SecureStore`, including device transfer. These source rules are not an executed backup/restore proof. Inspect final release resources and both-OS restore behavior before acceptance.

Assigned-record encrypted snapshots remain not started. No unrestricted query cache is persisted. Android pre-patch AES/plaintext-negative/offline/restart/purge subset evidence exists in [DRAFT_EVIDENCE.md](DRAFT_EVIDENCE.md); final patched client and native iOS results remain distinct open gates.

## Backend files and sharing boundaries

`agents/backend/src/routes/inventory.ts` authorizes finalized document access against authenticated tenant/team membership, validates bounded file types/basic signatures, and uses generated storage names; `src/middleware/private_uploads.ts` blocks the finalized `/uploads/properties/:id/documents` static tree. Public listing images intentionally remain publicly served. Existing signed document/brochure routes are separate capability boundaries, not a claim that all uploads are private. Pending wizard/staging documents still need an authenticated staging contract and are not integrated into native UI. See [SECURITY.md](SECURITY.md).

Selecting a share target transfers a temporary file to another app via supported OS sharing. Private document sharing prompts the user; account/session/abort guards run before handoff. A share sheet already opened cannot be retracted by logout, and a chosen target may retain/send its own copy outside app control. The app does not select an exact WhatsApp recipient, send automatically, or confirm delivery. Real WhatsApp/Business/mixed-media/provider checks remain open. Google treats transfers to other apps as a sharing boundary, with defined exceptions including qualifying user-initiated actions; final store classification needs owner review of the actual shipped flow, not a blanket “no sharing” answer. [Google Data safety guidance](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en).

Backend CRM/uploads/logs/backups retention and deletion-request operation are not settled by the 24-hour local draft lifetime. No production retention, restore or private-file cleanup schedule was verified. Current routine request logger removes identifier paths/capability queries and telemetry tests cover selected credential/body fields; broader legacy route/provider capture remains open (`agents/backend/src/middleware/request_logger.ts`, `src/instrument.ts`, `src/utils/capture.ts`; [SECURITY_REVIEW_EVIDENCE.md](SECURITY_REVIEW_EVIDENCE.md)). No mobile analytics/crash SDK initialization was found in inspected app/source; dependency/native third-party data behavior still requires final release inspection rather than a claim of zero SDK collection.

## Actual native permission declarations

`android.permissions: []` does **not** mean an empty merged manifest. `agents/mobile/app.json` explicitly blocks `RECORD_AUDIO`, `READ_CONTACTS`, `READ_CALL_LOG`; image-picker microphone permission is false. Inspected generated debug manifest: `agents/mobile/android/app/build/intermediates/merged_manifests/debug/processDebugManifest/AndroidManifest.xml`, with provenance in `android/app/build/outputs/logs/manifest-merger-debug-report.txt`. No broad photo/video permission-policy defect is established by this snapshot. Google requires `READ_MEDIA_IMAGES/VIDEO` only where minimum-scope pickers cannot support core functionality; recheck actual release artifact rather than reporting a permission the app does not declare. [Current Google sensitive-permission policy](https://support.google.com/googleplay/android-developer/answer/16558241?hl=en). Expo documents automatic module permissions and microphone blocking in [ImagePicker](https://docs.expo.dev/versions/latest/sdk/imagepicker/).

Generated iOS `ios/RealtyPandit/Info.plist` has camera “Take property photos to attach to this listing.” and photo-library “Choose property photos to attach to this listing.” strings. It also contains default Face ID text from SecureStore even though local biometric unlock is unused, plus Expo dev-launcher local-network explanation/Bonjour service. No microphone/location usage strings were found in this generated file. Inspect shipping Release Info.plist/entitlements, appropriate unused purpose-string removal, limited-library/cancel behavior and privacy manifests on a full Xcode build. Presence of Face ID text is not evidence of biometric collection; native iOS has not run.
