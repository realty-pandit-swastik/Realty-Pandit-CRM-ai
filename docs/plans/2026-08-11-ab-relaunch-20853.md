## Launch sequence

### Step 0 — Pause everything currently running (lesson 6)

Overlapping campaigns starve each other in the auction; on 2026-05-25 this reduced WA-Status to ₹4
of delivery. **Confirm zero ACTIVE campaigns before creating anything.**

Pause: `120253692368960547` (A, 20913) and `120253692400010547` (B, 20913), plus any other ACTIVE.

### Step 1 — Resolve the creative

Resolve `Db3cHubsOhF` → IG media ID → video/image ID usable as ad creative.

### Step 2 — Arm A: CTW + prefill · ₹200/day

- Objective **OUTCOME_ENGAGEMENT**, goal `CONVERSATIONS`
- `destination_type=WHATSAPP`, CTA **`WHATSAPP_MESSAGE`**
- 🔴 **NEVER `MESSAGE_PAGE`** — routes to Messenger, burns budget, produced 0 leads for ₹696
- `whatsapp_positions=["status"]`
- **Prefill text must carry the listing code:**
  `Hi, I want details about the 2 BHK builder floor at Nyay Khand I, Indirapuram - RP-GZB-RES-20853`
  This removes the Graph-API dependency in `extractDisplayId` — the customer's own first message
  carries the code even if `fetchAdDetails` fails.

### Step 3 — Arm B: Instant Lead Form · ₹200/day

- Objective **OUTCOME_LEADS**, `LEAD_GENERATION`
- New lead form bound to the ad
- Form name and ad name both carry `RP-GZB-RES-20853`

### Step 4 — Targeting (keep byte-identical to prior runs)

Same 4 pins, `age_min=30`, max 65, Android+iOS, `advantage_audience=0`.

⚠️ **Check the Vaishali pin covers Indirapuram.** 20853 sits ≈2 km from the Vaishali pin
(28.6465, 77.3388) — within radius if ≥5 km, but **verify rather than assume**. 20913 was only 0.8 km
inside, so this is a larger offset than last time.

### Step 5 — Pre-launch gate (all must pass)

1. `destination_type=WHATSAPP` on A
2. CTA is `WHATSAPP_MESSAGE`, not `MESSAGE_PAGE`
3. `age_min=30` held
4. `whatsapp_positions=["status"]`
5. Prefill text contains `RP-GZB-RES-20853`
6. Both ad names contain `RP-GZB-RES-20853`
7. Both campaign names contain `RP-GZB-RES-20853`
8. B is `LEAD_GENERATION` and bound to the new form
9. All older campaigns confirmed PAUSED
10. `extractDisplayId` returns `RP-GZB-RES-20853` from every string, listing resolves + active, and
    `buildDemandFromInventory` stamps `{intent:buy, BUYER, bhk:"2", area_min:900, …}`

### Step 6 — 🔴 Price-consistency check (NEW — do not skip)

The listing carries **two prices**: `price`/`customer_price` ₹50 L and `display_price` ₹55 L.
The ad will say **₹55 L**.

**Before launching, confirm the WhatsApp property card and the website both render `display_price`.**
If either renders `price`, a lead sees **₹55 L in the ad and ₹50 L on the card** — which reads as
either a bait-and-switch or a ₹5 L discount. Both are bad, in opposite directions.

## Read the results correctly

- **Do not judge before 72–96h** (lesson 12). At 30h the previous test showed B ₹31 vs A ₹42; the
  true answer was clearer, and different, by day 5.
- Judge on **cost per real CRM lead**, not Meta's "results". A's result is a *conversation started*;
  B's is a *submitted form*. Those are not comparable — on the 20528 test A looked cheaper per result
  (₹30 vs ₹51) but was **3× more expensive per actual lead** (₹152 vs ₹51).
- Verify in the CRM: `select count(*) from contacts where meta_campaign_id = '<new id>'`.
